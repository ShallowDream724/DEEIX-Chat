# MiMo 流式朗读验收（2026-11-14）

## 交付范围

新增 `mimo-v2.5-tts` 朗读渠道，独立服务地址和加密 API Key，沿用管理页分区标题保存。用户默认冰糖、较快，提供八种官方音色、三档语速、自定义风格及恢复默认，不附带速度解释文案。渠道默认值集中定义；个人偏好按渠道保存，不重置 DeepSeek 旧音色，不改变全站默认浏览器输入。

API 使用 `stream=true` 与 `audio.format=pcm16`，从 SSE 音频增量转换为未知长度 WAV 流。服务端以 32 KiB 缓冲落盘、传输，客户端最多提前排队约半秒；停止释放本地读取和播放资源，不提交剩余段。已受理的当前段完成并进入有限缓存，供重播复用。无额外文本改写模型、声音设计或声音克隆调用。

- 同条件浏览器重播不新增合成，服务端使用省略参数的默认配置请求命中同一音频；重播中取消后 AudioContext 创建/关闭数量相等。

## 内容与资源边界

整篇规范化文本最多 100,000 加权字符、256 KiB；单请求始终遵守渠道能力，MiMo 为 1,200 加权字符/16 KiB，不把三万字符一次塞给模型。每段有 30 分钟异常音频保护，整篇不在累计 30 分钟时截断。长文不会并行预生成整篇，内存不随累计音频长度增长。

代码、Mermaid、复杂公式源码使用简短提示，连续省略块合并；链接保留标题、移除网址，表格保留表头及逐行文本，不宣称数学口语化或表格语义总结。编辑正文改变合成身份；仅虚拟滚动卸载不会停止音频。

缓存容量是全站音频总上限；先回收过期和未占用的旧完整音频，不删除活动文件来强行挤出空间。若空间均被活动任务占用，仍会限制新写入。空闲清理按分钟运行；被读取的到期文件在最后一个句柄关闭后回收。用量/请求记录的 30 天规则独立于音频期限。已过期音频由下次明确播放重新生成，不自动重复收费。

真实请求速度是本机单次测量，不承诺所有网络环境都相同。Windows 上另运行 config 全包时，其既有 Unix 文件权限断言（0600 对 0666）失败，与本批配置逻辑无关；该包未改测试来掩盖平台差异。全局 Web 架构扫描仍有未纳入本批的 review 路由和 upload-mime 既有违规，语音改动无新增违规。
