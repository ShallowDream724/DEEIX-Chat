# 语音服务配置

管理员在「管理 → 语音」统一选择全站语音输入来源：浏览器、豆包输入法、微信输入法或 DeepSeek。默认使用浏览器；普通用户不选择供应商，也不保存个人语音来源。朗读回复单独开启，默认关闭。

语音输入选择 DeepSeek 或开启朗读回复时，页面显示 DeepSeek 服务地址与 API Key。两者共用独立语音密钥；尚未配置时，密钥字段提示必填并阻止保存，已配置后留空保存保留原值。密钥加密保存，管理接口只返回是否已配置。服务地址须为不含凭据、查询参数或片段的 HTTP(S) 地址，并通过本站的出站地址校验。浏览器输入不需要供应商密钥。

每段录音同时遵从本站配置和所选渠道的上限。本站录音上限可配置为 10–1800 秒；DeepSeek 完整音频转写的 120 秒渠道上限仍然生效。每用户语音并发请求数可配置为 1–8，默认 2。

例如，保持默认浏览器即可使用浏览器自身的语音识别；全站改用豆包时只需选择「豆包输入法」并保存。使用官方 DeepSeek 语音时选择「DeepSeek」，服务地址填 `https://api.deepseek.com`，在本页填写专用 Key，再保存；需要朗读则独立开启「朗读回复」。聊天模型配置不代替这些设置。用户在聊天设置中选择是否自动朗读和音色，无需知道输入渠道。

| 来源 | 识别方式 | 有效录音上限 |
| --- | --- | --- |
| 浏览器 | 浏览器原生实时识别 | 本站上限；浏览器还可能因静音或自身服务状态提前结束 |
| 豆包输入法 | 流式 | 本站上限；未证实上游总长硬上限 |
| 微信输入法 | 分批上传并返回中间文字 | 本站上限；未证实上游总长硬上限 |
| DeepSeek | 停录后完整音频转写 | 本站上限与 120 秒取较小值，音频不超过 8 MiB |

所有渠道均在当前有效上限剩余 10 秒时提醒，到限结束本段。突发断线无法提前倒计时，会立即结束采集并保留已有文字。连续点击开始新段默认换行；自动标点尽量由渠道完成，保留原话，不增加 AI 润色步骤。

用户默认免费使用语音。语音输入与朗读各有独立收费开关，默认均关闭；供应商产生的服务成本不会自动变成用户扣款。管理员开启收费后，所选服务端输入渠道按元/小时费率、实际音频时长向上取整到整秒计费；朗读按元/万加权计费字符收费。浏览器语音输入免费。

保留费率默认分别为 0.39 和 1.5，只有相应收费开关开启才向用户扣费，费率设为 0 同样免费。费率必须为有限非负数，最大 1,000,000。账本换算复用「计费」中的美元兑人民币汇率，无需另设语音汇率。

TTS 的计费字符中汉字计 2，其余 Unicode 字符计 1。每次朗读最多 10,000 计费字符、64 KiB 请求文本，输出音频最多 30 分钟；超限明确提示，不静默截断。音色从列表选择：海星（`stella`）和暗潮（`tide`）。打开列表不会触发合成；相同用户、文本和音色等条件命中缓存时复用音频，不重复合成收费。

## 动态配置

唯一配置定义位于 `backend/internal/application/settings/registry_speech.go`，在配置索引构造前与主注册表合并。命名空间为 `speech`：

| Key | 默认值 | 用途 |
| --- | --- | --- |
| `input_provider` | `browser` | 全站唯一输入来源：`browser`、`doubao-ime`、`wetype`、`deepseek` |
| `deepseek_tts_enabled` | `false` | DeepSeek 朗读回复 |
| `deepseek_base_url` | `https://api.deepseek.com` | DeepSeek 语音服务地址 |
| `deepseek_api_key` | 空 | 加密保存的 DeepSeek 密钥 |
| `max_recording_seconds` | `120` | 单段录音时长（秒） |
| `max_concurrent_per_user` | `2` | 每用户并发语音请求上限 |
| `charge_asr` | `false` | 是否向用户收取语音输入费用 |
| `charge_tts` | `false` | 是否向用户收取朗读费用 |
| `asr_cny_per_hour` | `0.39` | 所选服务端语音输入渠道人民币小时费率 |
| `tts_cny_per_10000_characters` | `1.5` | DeepSeek 朗读人民币万计费字符费率 |
| `cache_max_bytes` | `268435456` | 内部语音缓存总大小上限，必须大于 0；同时约束首播音频落盘 |
| `cache_ttl_hours` | `72` | 内部语音缓存保留时长，范围 1–8760 小时 |

注册表将这些值写入运行时 `config.Config.Speech`，现有汇率写入 `config.Config.BillingUSDToCNYRate`。管理保存通过既有运行时配置失效机制生效，不要求重启。语音请求在开始调用时获取一份运行时快照，供渠道选择、限制与价格结算使用；音频帧无需查询配置数据库或重复解密。

管理保存成功后会立即使当前页面与同源其他标签页的语音能力缓存失效；其他已打开的用户页面在重新聚焦、恢复可见或可见期间的定期刷新中获取新来源。新录音使用新来源，正在进行的录音保持其开始时的渠道，避免中途切换协议。

未配置 `input_provider` 时始终使用浏览器，旧版单个或多个渠道开关都不会自动替管理员选择来源。已有明确的 `input_provider` 保持不变，不新增强制迁移选择流程。旧用户 `chat.speech_input_provider` 偏好不再影响输入来源。DeepSeek 语音使用此处独立配置的 API Key，不借用聊天渠道密钥。

## 用量日志

语音输入和朗读以独立服务账本显示在管理用量日志与用户订阅用量日志中。模型/服务列展示本地化服务名和供应商；费用明细保持项目、用量、单价、金额四列。语音输入展示原始毫秒换算的实际秒数与向上取整后的计费秒数，单价按小时展示；朗读展示供应商定义的加权计费字符，单价按万字符展示。费用与计费量均读取调用时的账本快照，不用当前费率重算历史金额；单位与金额展示沿用用户选择的币种和换算率，并保留语音小额计费所需精度。

`pricing_mode=metered` 的语音账本保持独立，不作为聊天的基础服务合并，也不显示为零 Token 模型调用。原有基础服务账本仍按照既有规则合并到对应会话的聊天行。
