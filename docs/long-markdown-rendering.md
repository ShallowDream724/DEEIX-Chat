# 长 Markdown 渲染

## 历史消息窗口

`ChatHistoryWindow` 保留每条 `MessageScrollerItem` 的稳定外壳和消息 ID；首屏只挂载尾部 4 条内容，再通过共享 IntersectionObserver/ResizeObserver 加载视口及 1000px 预取范围。离屏内容卸载，外壳保留实测高度，宽度变化时重新估算。pending/streaming、编辑、焦点、文本选择和截图目标保持挂载；交互组件的会话状态与长表的页码状态存放在窗口外，消息离开会话后释放。

滚动定位仍由原 scroller API 执行。未知高度的远距离导航先挂载目标附近，再立即定位并校准一次；用户滚轮、触摸或指针操作取消后续校准。prepend 根据真实消息外壳识别，不依赖 content 第一个节点（它可能是截图品牌标记）；尺寸变化保留变化前的底部状态或可见消息锚点。直接落入未知占位内部时，只在首次测量按占位内比例保留当前行，后续真实内容变化不按比例重排。

Artifact 提取结果按当前会话的消息内容与身份复用；流式新片段不重新解析未变历史，移除消息和切换会话会释放缓存。

## 单条长内容

正文、用户消息和思考内容共用 `LongMarkdownStreamdown`。内容达到 16,000 字符或 300 行时使用 Streamdown 自带的 block parser；不自行按空行切分，保留引用定义和脚注合并语义。普通内容沿用原渲染入口。

长内容初始挂载前 8 个 block、活动尾块和包含标题的 block。其余 block 在距视口 800px 内挂载，访问后保持挂载，避免来回滚动丢失局部交互。标题始终存在于 DOM，供回复目录发现和定位。未挂载 block 使用估算高度占位；正文源内容始终保留，消息级复制和导出仍读取原消息。单个长段落仍是正常段落，不切成文本片段。

懒加载块在挂载前记录高度及滚动位置。仅当整条消息原先跨越视口、该块完全位于视口上方时，提交后按新旧高度差补偿滚动，保持当前阅读行；整条消息已在视口上方时交给历史窗口补偿。同批多个块共享累计补偿量。读者输入或主动滚动会取消待执行补偿，截图模式不补偿。段内补偿通过消息壳上的一次性 `data-markdown-anchor-adjustment` 标记通知历史窗口刷新高度但跳过重复修正。

生成过程中继续使用原有 `isAnimating`、`parseIncompleteMarkdown` 和 caret 设置。完成内容只借用 streaming 模式的 block 管线，保持无动画、完整 Markdown 解析。启用 `sourcePositions` 的调用保留整篇 static 解析，防止分块让源行号重新从 1 开始。

进入长内容路径后，独立 GFM 表格达到 200 行时，在构造 Markdown AST 和 React 行节点之前按源行分页，每页 100 行。普通表格保持原行为；与引用定义、脚注或其他内容联合成单个 block 的表格保守保留整体解析。支持单列表格、对齐标记、转义管道，以及 GFM 对缺少/多余单元格的补齐/忽略行为。流式表格默认跟随最后一页，读者主动翻页后保留选择。

稳定消息壳创建 `MarkdownViewStateStore` 并提供上下文，在历史窗口卸载正文后继续保留手选页。键由思考/正文段标识与 block 索引组成，每项仅保存数字页码与表头结构的短指纹，最多 64 项，不保留 Markdown 源。替换表头时重置，源行数减少时收敛到最后可用页；截图完整展开不会覆盖手选页。

分页只影响展示。Markdown 下载保留完整表格源，CSV 从全量源单元格生成并还原管道转义；格式化单元格在 CSV 中保留其 Markdown 源。普通小表格的 DOM 导出行为不变。

截图调用方须先展开消息窗口，再调用 `materializeMarkdownForCapture(root, signal)`，等待其完成后采集。该函数将目标内所有长 Markdown block 和表格行临时挂载，返回恢复函数，调用方在 `finally` 中释放。取消等待时函数先自行恢复再抛出，避免泄漏截图状态。

回归：`node --test apps/web/shared/components/markdown/long-markdown-{model,anchor,render}.test.mjs`。覆盖全量导出、页边界、尾部未完成行、转义管道、引用保守回退、标题保留、单列表格、阅读锚点、主动滚动取消，以及真实 Streamdown 分页在子树卸载后保留。浏览器验收应覆盖滚动到尾部、目录跳转、流式追加和手动翻页、长思考展开，以及截图后恢复分页。

## 代码与归一化预算

普通代码超过 16,384 字符或 300 行时，用完整的单文本节点显示源码，保留滚动、复制和预览，避免主线程 Shiki 分词及大量 token 节点。短代码继续高亮，Mermaid 与交互组件保留专门路径。

HTML 标签和 fence 范围先建立一次索引；nested fence 的启发式修复总检查数不超过事件数量的 16 倍，超预算保留完整原文，不截断输入。HTML visual fence 与 LaTeX delimiter 顺序扫描；嵌套 HTML 的 strong 修复由各组件处理自身后代边界，避免祖先重复遍历整棵树。

## 2026-11-13 验证记录

- 当前真实 Streamdown 依赖的合成 SSR 对比：600 段正文约 140ms → 28ms，2400 行三列表约 1880ms → 48ms。它们是本机 SSR 样本，不是生产浏览器 SLA。
- 浏览器合成验证：约 600 行/83KB 代码的代码容器只有 6 个后代节点；600 段正文保留 30 个目录标题，初次只挂载 16 段正文；2400 行表每页 100 行，第二页对应 101–200 行，CSV 下载含全部 2400 行。
- 历史浏览器验证：30 条混合消息初次挂载 3 条内容，底部 gap=0；追加至 180 条后挂载仍为 3 条，原可见消息的 top=-520px 保持不变。
- CUA 连接超时后，另用独立 Chrome 和实际窗口/Markdown 组件补验：180 条混合消息的中部滚动稳定；远距离跳转将第 40 条消息准确定位到视口顶部；连续 12 次往返跳转保持可交互，无未捕获异常。截图目标临时展开后含完整 600 段正文、2400 行表格，释放后恢复原 scrollTop 和可见消息；宽度变为 560px 后仍保留所在消息。另有首次占位替换、连续 20 次重挂收敛的确定性测试。上述合成验收不代表任意生产内容均已覆盖。
- 合计 50 项前端专项测试、完整 TypeScript 与 Next.js 生产构建通过；相关 Go 三包全测通过。全仓架构脚本仍报告既有未跟踪预览页的跨层导入及 `upload-mime.ts` 的类型断言，本批没有新增架构违规。
