# 对话输入与超限处理

更新：2026-11-04。本页记录本轮已实现的规则、验证和后续边界。改动已在本地验证，尚未发布新镜像；线上行为以运行镜像为准。

## 配置与有效上限

模型输入预算采用一套系统默认值，再按渠道逐项覆盖，不区分同一渠道的调用协议。留空继承，显式 0 取消该项额外运营限制。供应商已知的硬限制、模型能力和上下文窗口仍独立生效。

| 项目 | 系统默认 |
| --- | --- |
| 单条消息附件数 | 10 个 |
| 最终编码请求体 | 100 MB |
| 图片数量 | 20 张，包含本次实际携带的历史图片 |
| 处理后单图 / 图片合计 | 5 MB / 20 MB |
| 原生文件数量 / 合计 | 10 个 / 50 MB |
| PDF 单份 / 合计 / 合计页数 | 50 MB / 50 MB / 200 页 |
| 原生音视频合计 | 50 MB |
| 单文件解析正文保护 | 2 MB / 256,000 tokens |

页面使用十进制 MB。图片按缩放后的发送副本、Base64 编码前计量；原生文件按原件计量。50 MB 原生文件加 20 MB 图片编码后约为 93.3 MB，余量用于文字、工具定义和结构；最终请求仍按实际编码字节校验，不承诺任意组合都能同时满载。

单条消息附件数与完整请求的图片数/原生文件数不同。Chat01 将来若要求整个请求内所有类型合计最多 10 个附件，需要独立的混合计数约束，不能用当前这三项推导。

旧的全局单消息附件数迁入系统默认，已有渠道覆盖和管理员明确保存的值不被新默认覆盖，包括显式 0、272K 全文 token 等。仅未编辑的旧默认种子值会升级；未发布过的协议分层预算草稿由独立形状迁移收敛为当前设置。没有新增数据库表或聊天记录字段。

## 检查时机与结果

| 检查 | 时机与行为 |
| --- | --- |
| 上传原件类型、分类大小 | 添加时尽早反馈；上传服务读流和检测类型后复核。超过上传限制不能依靠稍后的缩图放行 |
| 用户累计存储额度 | 持久化上传时检查，返回独立的“存储空间不足”。渠道发送失败不会删除已经上传的原件，之后仍可复用 |
| 单消息附件数 | 添加时按可用渠道预检；正式发送、重试和切换路由按实际渠道检查 |
| 模型能力与当前/历史文件可用性 | 切换模型后预检已知问题；发送时核对当前分支全部有效附件的权限、原件与处理路径 |
| 图片数量、处理后大小 | 当前和历史图片共同计量；处理完成后、调用上游前校验，不自动保留最新 N 张 |
| 原生文件数量、大小、PDF 页数 | 预检已知元数据；准备原件与最终请求时再次检查。超限停止，不丢掉旧文件或改用文字绕过原生预算 |
| 解析正文大小、token | 取得完整提取结果后判断全文/RAG 路径；没有合法路径时停止，不截取前半部分继续 |
| 模型上下文 | 完整组装文件、历史、系统内容和工具后校准并检查；关闭自动压缩时超限停止，不裁掉旧轮次 |
| 编码请求体 | JSON/multipart 实际编码后、发送上游前检查，包含 Base64 开销；与用户存储空间无关 |
| 临时入口资源保护 | 最多 100 条消息，单条 20 万字符、合计 100 万字符；保留配置的临时附件总数和入口请求体保护，超限明确拒绝 |

自动压缩开启时复用已有压缩预检，重建请求后仍超限就停止。文本摘要不会自动减少图片数量或音视频原件大小。工具续问同样检查完整有效上下文；已经发生的调用保留其输出与实际用量，不能把后续拒绝说成整轮没有调用过模型。

## 模型切换与文件语义

- 切换模型本身可以完成。已知问题在输入区域展示，点击发送时用统一弹窗说明，不在每次切换时弹窗，也不自动切回旧模型。
- 原生可用时可直接发送，后台解析不阻塞；切到不支持原生 PDF 的模型时，可以使用现有且被允许的完整解析/RAG 路径。
- 历史或当前附件既不能原生处理，也没有可用解析路径时，拒绝本次发送。例如 Gemini 音频切到不支持音频的模型，不会静默忽略音频。
- 原生大小/页数超限与“模型不支持原生”不同，前者不通过降级文本来绕过。
- PDF 解析不再使用旧全文设置截取前 20 页。旧页数配置保留读写兼容，但不决定全文资格、不传入临时附件或 embedding 回退提取。原生 PDF 合计 200 页是独立的模型输入预算。
- 明确使用 RAG 时，正常无命中允许继续；检索系统故障且不能合法回退全文时停止。

一个平台模型可路由到多个渠道。预检尚不知道最终渠道：允许按候选中最大的单消息附件名额添加，只提前阻断所有候选都确认的同一个问题。原生标签采用保守就绪判断；它不是最终路由承诺。发送时按选中的渠道检查并返回实际生效上限，不改变原有优先级、随机路由或熔断策略。

## 普通与临时会话共用的边界

`shared/inputlimits` 负责预算解析；会话层共用完整输入的上下文判断和媒体校验；HTTP 与 SSE 使用同一结构化错误详情。前端只识别已知原因和安全数值，不解析供应商自由文本。

普通会话沿用当前分支的可信输入观测。临时会话使用最多 1,024 条、30 分钟过期的进程内缓存，只保存指纹、计数和过期时间，不保存提示词、文件字节或密钥。键包含认证用户、会话、路由和已完成祖先内容；编辑、重试、路由变化或缓存丢失后使用保守估算。多实例未命中也按此规则处理，不信任客户端报来的 token 数。

适用观测时采用“上一轮实测输入 + 内容变化估算”，下一次可靠响应重新校准。首次高估允许发生，不滚动累积无校准的估算。最新上下文用量与多次工具调用的累计计费分开。含本地工具结果、下一轮无法完整重建的 Responses 状态只在本轮续传，之后重新发送可重建的完整历史。

临时模式保留不持久化聊天、断开即取消等生命周期。它与普通聊天共用限额和错误含义，不因此新增持久化记录或断线续传。

## 用户提示与草稿

数量和字节上限使用“所选渠道”，能力和 token 窗口使用“所选模型”；正文数值来自实际规则。上传失败、存储不足、模型不支持、文件失效、输入超限分别提示。

| 场景 | 提示方向 |
| --- | --- |
| 单消息附件过多 | 所选渠道单条消息最多添加 N 个附件，请减少附件 |
| 历史图片使请求超限 | 本次发送包含 N 张图片（含历史图片），所选渠道最多支持 M 张；修改当前附件或新建对话 |
| 单份 PDF 超限 | 指出文件名与有效上限，建议拆分 |
| 历史音频无法处理 | 所选模型无法读取对话中的音频；切换模型或新建对话 |
| 当前消息过长 | 当前文字及附件本身已超预算，建议精简或减少附件；不只提示换对话 |
| 对话内容过长 | 历史积累后超预算，建议新建对话；token 数明确标记估算 |
| 存储空间不足 | 请前往“文件”清理空间后重试 |
| 文件已删除 | 当前附件可重新上传；历史附件提示新建对话后重新上传 |

多个已知原因合并为一个弹窗，复用原有 AlertDialog、按钮、主题和国际化。只有真实可执行的操作才展示。新建对话不携带旧历史、不自动发送，普通模式保留项目归属；目标输入框已有草稿时不覆盖。

发送前已知阻断发生在清空输入框之前，草稿和附件原样保留。提交后失败尊重“发送失败后自动恢复草稿”设置，并核对会话/分支及输入修订号，不覆盖后来输入的新内容。普通、排队和临时发送遵循同一恢复约定，保留原始草稿空白。

删除文件的单个与批量确认现说明：删除后不能预览或下载，引用该文件的对话可能无法继续发送。原有聊天文字不会因此消失。本轮不增加关联对话枚举或删除后卡片联动。

## 验证与预览

针对共享预算、设置迁移、普通/临时上下文、提取、embedding、内置 PDF 解析和 HTTP 错误进行了回归。真实 21 页 PDF 用例确认最后一页进入临时会话的上游输入；超出全文保护时上游调用次数为零。还覆盖历史媒体不兼容、渠道覆盖、显式不限额、候选渠道不同预算、工具续问和观测隔离。

前后端构建及 Web 类型检查通过。界面用真实组件在桌面和 390px 手机视口检查，包含浅色、深色及多原因。没有调用付费上游模型，也没有发布镜像。本地后端重启被执行策略拦截，运行中的旧进程尚未切换到新程序。

开发预览：`/input-limit-review?scenario=count&theme=light`。场景支持 `count`、`size`、`unsupported`、`context`、`multiple`；生产环境该预览页返回 404。

## 后续排期

- 历史消息编辑时增删/替换附件：沿用分支语义，重新计算预算和观测，不等同于删除文件管理中的原件。
- 图片转文字摘要、上下文进度环与压缩策略一起设计；本轮不默认转换。
- 生成文件单文件/单轮保存保护和允许一次超出用户存储额度另行实施，不能由本轮输入预算推导。
- 文件侧栏预览、删除文件后的引用联动、Chat01 渠道继续按 [总排期](FORK_ROADMAP.md) 推进。
- 暂时隐藏桌面客户端下载入口和后台下载设置，保留原配置。待近期功能稳定后发布自己的 Windows 安装包，再替换下载及更新地址；Android 后续评估，macOS/iOS 暂不开发。
