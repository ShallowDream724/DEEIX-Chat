# DeepSeek 与语音开发验证

日期：2026-11-14。本记录只描述开发环境结果，不代表已发布或真实手机验收。

## 真实上游小样本

全部采用合成资料，未上传用户聊天、录音或私有文档。专用开发凭据不进入源码、浏览器或生产配置，无自动付费重试。

| 项目 | 结果 |
| --- | --- |
| Flash 原生搜索 | Chat、Responses、Messages 均 HTTP 200；上游分别报告 `tool_search=3/3/4`。Messages 的一个结果块不等于一次搜索计费。脱敏结果已作为回归 fixture。 |
| Excel | 15,658 字节、两工作表，含公式缓存、日期、前导零、合并标题、图片及图表。官方上传约 2.25 秒，Flash 回答约 1.08 秒；图片数字码未读到，合计回答 352.9，与缓存值 353.4 不符。仅凭模型输出不能将差异归因于解析器。 |
| 本地 Excel | 同一文件现有解析器首次约 1.62 毫秒、10 次中位约 1.06 毫秒，公式缓存、日期、编号正确。因此保留本地默认；不能推广为任意工作簿都只需此时间。 |

| DeepSeek 语音 | 官方 TTS 生成 5.56 秒测试音频，官方 ASR 正确转写。通过本站 API 重测转写约 1.33 秒，同 request_id 返回同一记录。 |
| 本站朗读 | 短文本首 4096 字节约 1.02 秒到达，最终 107,564 字节；完成后相同内容的新 request_id 复用同一音频 ID，未新建合成账单。 |

| 豆包输入法 | 最终复测约 8.88 秒，18 个有效事件；多次 partial 明确早于客户端 finish，最终保留完整两句。相同身份复用，不更换设备规避服务端限制。 |

时间包含该开发机器及当时网络，仅为单样本观测。DeepSeek 流式 WAV 使用未知长度头 `0xFFFFFFFF`，已按真实音频修正解析并加入回归。

豆包初测在上游纠错阶段观察到累计文字缩短。随后用户明确选择保留输入法自带的纠错与最小整理；早期“过滤整批 nonstream_result、只保留字面识别”的规则已移除。真实多停顿测试证明后续批次同时包含旧句纠错与新句识别，整批过滤会丢掉新句。现以无索引结果的首候选作为整段累计快照，包括上游修订；空首项不回落到辅助旧句，也不清空草稿。保持已验证的二遍配置，直到 SessionFinished 成功才完成本段，不以分句结束标志停止录音，也不以最长字符串猜测纠错结果。

本机测试库为 self 模式；四条语音操作各对应一条账本，ASR 原始单位毫秒、TTS 加权字符，重复转写/缓存播放未增加操作账本。这里的本站金额为 0 不代表供应商免费。费率换算、向上取整、余额预留和历史快照另由计费测试覆盖。

初始官方余额 32.92 元，后续观测 32.83 元；余额只显示到分且结算可能延后，不能用一次余额未变宣称请求免费。所有测试仍在本轮 1 元预算内。

## 边界与自动检查

- 后端覆盖三协议工具用量与状态续接、Files 并发与用户/凭据隔离、不明上传查询恢复、Fetch 预留合计、临时状态隔离、内容审核清除状态。
- 语音覆盖短期连接票据、用户隔离、请求重放、结果不明禁止自动重试、音频限长/背压、取消与服务关闭、缓存配额/过期、终态并发读取及实际返回 URL 可访问；新语音包通过竞态检查。
- 64 项相关 Web 回归通过，覆盖草稿分段、尾包、取消、迟到事件、发送恢复与临时分支、自动朗读幂等、付费合成与播放分别去重、媒体活动资源释放，以及独立语音计费展示。
- 手机价格弹层触摸打开与关闭，原菜单 DOM、分组、scrollTop=430 和焦点保留，没有触发模型选择。
- 浏览器播放器验证初始 Play、音频播放、切视频停止旧音频、不支持格式提示、静音视频归静、减少动态及手机侧栏隐藏；两侧各两条导航只影响现有线条，点击矩形没有变化。
- Web 类型检查与生产构建通过；生产构建包含按需加载的 Opus Worker/WASM。
- 真实聊天组件检查了桌面、390px 手机、820px 平板布局；实际 AudioWorklet 收到 10,752 个 PCM 样本。发现并修复发送回调读到旧草稿的问题，唯一发送请求正文包含停止后的最终尾句；转写中编辑、取消和换会话隔离通过。浏览器自带识别没有额外申请麦克风，只显示明确状态。
- 管理员语音页面桌面/手机无运行时异常，390px 下没有横向溢出。语音 WS 与现有 CORS 共用白名单和桌面 WebView 规则。
- 文档上传复用原件字节与小型 multipart 头尾，避免再复制整份文件；音量活动不逐帧重渲染消息列表。

本机使用已有 Go 1.26.4 和临时 modfile 执行后端构建与测试，仓库要求的 Go 1.26.10 未改动，也未触发工具链下载。正式 CI 仍按仓库版本执行。已有 config 包的 Windows 文件权限测试（0600 与 0666 差异）和未跟踪 review 页面的架构检查噪声不属于本批；本批相关测试与类型检查通过。

仍需用户实际设备、生产反向代理及网络环境验收。输入法上游总录音时限未获证实，站内上限与提前 10 秒提醒持续有效。

## 管理员来源与录音交互复核

本轮新增的浏览器与 HTTP 验证不调用付费语音或模型 API；前述真实上游测试保持为历史证据，不与模拟测试混称。

- 实际 HTTP 验证默认 `browser`、两个用户收费开关为 `false`、能力返回 `Cache-Control: no-store`，客户端无法请求管理员未选的来源。用户设置不再返回 `chat.speech_input_provider`。DeepSeek 缺少独立语音 Key 时，服务端拒绝保存并指明该字段；聊天凭据不参与校验。
- 实际管理员页面完成选择豆包、保存、切回原浏览器的闭环；缺少语音 Key 时字段提示并禁用保存。桌面和 390px 页面无运行时异常、无横向溢出，测试后保留原配置。
- 真实聊天组件与 fake media device 执行 13 项生命周期验收：轨道结束/静音、音频上下文挂起、权限拒绝/撤销、设备移除、处理器异常、取消后的迟到采集、刷新保留文字、定稿光标、管理员来源变化、同一 Chrome 音轨共享及不支持重载后的释放回退。供应商与 Web Speech 返回通过受控模拟注入；不将这些测试等同于所有实机的操作系统抢占行为。
- 录音与 composer 行为回归 27 项通过。另直接检查桌面/手机录音操作行只有三个 44px 无文字按钮，取消后操作行立即消失，运行时异常为 0；正文与普通工具栏不在录音底部重复显示。
- 支持 `start(audioTrack)` 的已确认桌面 Chrome 分支共享一份实际麦克风轨道；其余浏览器保留原生识别，不为波形再次采集。静态与真实音量反馈边界见 [前端语音](speech-frontend.md)。

- 当前 Web 生产构建通过（44 个静态页面），保留用户原有 `next-env.d.ts`。后端设置、用户设置、应用接线、语音服务、HTTP 层及供应商协议六包通过竞态测试。新增并发用例将首次请求阻塞在授权阶段，证明重复 ASR 请求只授权、调用上游和计量一次；微信最终纠错策略已按下方新样本复核更新；回归覆盖结束纠错优先、旧纠错不回填及真实错误保持失败语义。

## 录音栏与左侧律动视觉调整

- 录音按钮由 44px 缩至 32px，操作行由 68px 缩至 44px，波形高度 24px；透明触区 40px。真实组件截图覆盖桌面 2 倍缩放与 390px 手机，启动提示背景透明，三个按钮尺寸正确，无横向溢出或运行时异常。
- 最终仅左侧位置导航律动，右侧目录保持静态。复用现有音频图取得 8 个真实频段，线条保留 2px 厚度和 10px 中心间隔；没有独立频谱时不伪造多条动态。少于 8 条时合并频段，1–2 条也覆盖中频而非仅采样频谱两端。
- 低频改为从中间向上下两端展开，混合少量真实全频节奏让边缘参与，最长约 133ms 延迟由固定 5 帧缓冲产生。实际音频/视频强段连续三帧中，左侧约 17–37px，形态上下对应、中间较长、边缘也参与；右侧宽度、透明度、变换及按钮位置不变。不将静态截帧或宽度数值等同于所有素材的节拍效果。
- 左右边栏同时展开时正文左内边距实测 32px；折叠左栏或关闭右预览恢复 24px，仅增加 8px。伸长区域 hit-test 到达正文，导航按钮矩形不变；暂停恢复原宽。截图与原始测量位于 `.cache/local-dev/left-center-spectrum-final-result.json`、`speech-review/left-center-spectrum-*.png`。
- 频谱固定音调、音量响应、共享缓冲、静音及清理等 7 项媒体活动回归，29 项语音回归，4 项导航频段/静音/退出回归通过。Web 类型检查、定向 lint 与生产构建通过。

## 光标与停顿后续说

- 独立 Chrome 中的真实聊天组件完成 8 项光标验收：起录聚焦、60 次 partial 后跟随末端、鼠标/方向键/手动编辑立即中断并隔离迟到结果、中英及 emoji 中间插入保留后文、长内容只滚动输入框、旧识别对象错误隔离，以及 DeepSeek 转写前手动中断不上传、不发送。识别返回采用受控模拟，不能当作上游稳定性证明；证据在 `.cache/local-dev/speech-caret-qa/results.json`。
- 启动和转写状态仅保留小 spinner，完整说明供屏幕阅读器读取；空草稿录音没有状态长占位文字。最后 10 秒显示数字倒计时。
- 豆包真实上游使用 24.68 秒合成音频，三段之间各静音 4 秒。修复后累计文字变化 48 次，两次停顿后各继续变化 16 次，并保留 2 次上游纠错；最终结果从旧过滤规则下的 25 字恢复到 61 字。真实响应结构已脱敏为 `backend/internal/infra/speech/testdata/doubao-vad-pauses.json`，包含混合新旧候选、空首项、分句结束与最终尾包回归。语音供应商、应用及 HTTP 三包竞态测试通过。
- 重建后端后完成独立 Chrome 的完整链路验收：合成音频通过实际 AudioWorklet/Opus 编码、本站 WebSocket 与真实豆包上游，共发送 1,260 帧、收到 48 次文本事件，三个阶段可见文字长度递增为 25/35/60，停止后最终 61 字与上游 final 一致；无运行时异常、无聊天模型请求。证据在 `.cache/local-dev/doubao-pauses-browser-e2e.json`。保留开发库当前的豆包选择，不更改用户配置或调用 DeepSeek 付费接口。

## 到限收尾、流动反馈与内存复核

- 独立 Chrome 的真实 WebCodecs 编码实测：50 个 20ms PCM 输入在 flush 后输出 51 个 Opus 包；6000 个输入输出 6001 包。原后端按包数严格拒绝大于 120 秒的输入，导致正常到限误报。现保留最多 80ms 的编码尾包，最多等待 1 秒收尾，计量仍不超过有效录音上限；超过尾窗继续拒绝。共享浏览器识别音轨先通知识别停止，再释放轨道，避免将正常到限当作设备故障。
- 新后端完成真实 120 秒浏览器至豆包链路验收：自动到限后完整发送 6001 包、收到 230 次文本事件，最终 356 字与上游 final 一致，没有错误事件、运行时异常或聊天发送。证据为 `.cache/local-dev/doubao-limit-browser-e2e.json`；此样本包含停顿，不能代替连续快说复现。
- 左侧律动保留 2px 线宽、10px 中心间距、原命中区域与右侧静态导航。每次仍只采样最多 30Hz，通过相邻频段平滑、连续延迟插值及 CSS 过渡连接变化。真实音频/视频各 120 个显示帧里，目标值分别变化 46/45 次，画面分别有 118 次连续变化；停止后立即恢复，无正文命中拦截、无运行时异常。5 项导航回归通过，证据为 `.cache/local-dev/left-flow-*-motion.json`、`left-flow-final-result.json`。
- 录音采集、16kHz 降采样、Opus 编码、频谱与显示均在客户端。流式服务器使用容量 32 与 16 的有限帧队列，微信另聚合最多 6 帧；按协议帧最大 1275 bytes 计算，音频队列约 69KB，另有协议、连接、文本与运行时开销，不能把此数视为总 RSS。结束、取消与断连释放会话及连接，不持久化 ASR 音频；上游服务自身的保存行为不属于本站实现。
- DeepSeek 非流式需要整段 WAV：120 秒 PCM16 约 3.84MB，客户端构造 WAV Blob 后立即清空 PCM 分块引用，服务器使用原字节加小型 multipart 头尾转发，不再额外复制整段录音。有效 multipart、Content-Length 和转录结果通过本地 HTTP 验证；预分配 3.84MB 输入的离线转发基准约 38KB/op 附加分配，未调用付费接口。该数是分配量，不是请求总内存峰值。入站 multipart 解析仍早于识别服务的并发准入，上传阶段压力需独立评估，不宣称任意数量的同时上传都受识别并发数限制。
- 到限与取消光标的 6 组真实 Chrome 组件回归通过：共享音轨先停止识别再释放、原生浏览器计时到限、实际编码 50 帧后完整发送 51 包并正常定稿，以及已有草稿/中间插入/空草稿取消后聚焦全文末尾。`speech-limit-qa/codec.json` 记录实际编码包数，`ui-results.json` 记录组件行为；此组供应商返回采用模拟。
- 键盘的 9 组真实 Chrome 回归通过：Enter 只停止、按住重复不误发、修饰键及复制保留录音和光标、普通编辑/全选/粘贴结束本段、原生 IME 组词及确认不发送、Tab/Escape 保留原生行为、Ctrl+Enter 只停止，以及丢失 keyup 后的新按键恢复。生成请求为零，运行时异常为零；证据在 `.cache/local-dev/speech-keyboard-qa/results.json`。36 项语音业务回归、5 项导航回归及相关类型/lint 检查通过。
- 微信用新的会话 UUID 进行了离线 SAPI 三句不同事实的真实上游测试，两次停顿后仍完整保留全部事实，并采用本次 END 的最终纠错。豆包 60.84 秒连续合成样本的首候选更新 200 次、最终 325 字，仍未复现用户真人连续快说时的卡住；没有新增字数门槛，也没有据短样本把原因归于上游。与作者当前版本的差异和有效样本边界见 [VoiceKey 核验](voicekey-streaming-audit.md)。
