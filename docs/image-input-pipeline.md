# 图片输入与附件修订

2026-11-13，代码已推送自有 fork；镜像发布被 GitHub Actions 禁用响应阻断，详见 [发布记录](FORK_ROADMAP.md)。覆盖 Web 普通/临时对话、消息编辑、文件库和知识库上传。头像裁剪使用原独立入口；模型生成的 GIF/视频产物不适用输入图片的静图限制。

## 数据与处理边界

浏览器读取原文件，在 Worker 内解析容器并计算 SHA-256，按来源指纹查询已保存成品。命中时不解码、不压缩、不上传原文件；未命中才准备成品，只上传这份成品。数据库保存原始 SHA、大小和策略与成品 fileID 的映射，不保存原图。上传至本站一次与本站发送至模型是不同的传输阶段；不会先上传原图再上传压缩图。

最长边来自既有 `file.image_max_dimension` 对应运行配置 `ImageMaxDimension`；当前用户选择 1536 不构成覆盖其他部署设置的迁移。0 保持不缩放。策略身份为 `image-normalize-v1:<dimension>`；缺少新策略字段的旧后端使用不缩放、无来源别名的兼容路径。

- 已符合尺寸、方向、静图与 sRGB 条件的 JPEG/PNG 保留原字节，不进行重复有损编码。
- 需要处理时使用原生缩放解码或 `createImageBitmap`，修正 EXIF 方向，绘制到 sRGB/unorm8 Canvas。JPEG 一次编码质量 0.9；PNG/WebP/静态 GIF 转 PNG，保留透明度。PNG16 的明确 SDR 输入可转 PNG8。
- 仅对已完成 sRGB 转换的新 Canvas 编码结果移除冗余色彩配置，避免成品重新选择时被再次编码。未知原始 ICC 先转换，不根据配置名称猜测色彩空间。
- 普通 MPF 与已确认 SDR 底图的 Adobe gainmap JPEG 可读取 SDR 主图；解码前移除辅助图。明确 HDR 底图、无法确认底图含义的 HDR 编码仍给出明确不支持提示，不实现自定义色彩转换算法。
- GIF、APNG、动画 WebP 独立识别。当前没有启用已验证能读取完整动画的对话路由，不能默默只发首帧。文件库可原样存储动画，不登记静图策略别名；生成动画仍正常保存、预览、下载。

成品大小沿用管理员单图上限，未设置则继承默认附件上限；分类显式值可以高于默认值。允许格式也按实际成品检查。没有新增 3MB/6MB 目标或按体积反复压缩的前端循环；渠道实际图片/请求体限制仍在发送时校验。

## 并发、缓存与失效

端侧最多两个可复用 Worker，按任务预计工作集准入，总预算 256MiB；源文件保护 64MiB、像素保护 64MP。PNG16 按较高解码成本估算，不能仅按压缩文件大小分配并发。正常任务归还 Worker，取消/超时销毁当前 Worker，闲置 30 秒回收，大源文件任务结束后回收。成功准备结果弱关联原 File，最多 8 项/32MiB、2 分钟，不将原始 4K/8K 文件作为持久缓存。

上传网络并发与 CPU 调度独立。来源查询合并同时到达的请求，每批至多 100 项；策略查询短期共享，策略变化最多刷新一次。临时对话只保留本地规范成品；重试与分支使用稳定 assetID，重新生成临时 fileID 不改变内容身份。

缩略图使用实体级资源池：账号范围、持久 fileID 或临时 asset、内容版本与缩略规格共同标识；URL 不参与身份。多个组件共享进行中的生成任务及小图 Blob。卸载只释放订阅，不销毁其他使用者；单个订阅取消不取消其他订阅。闲置缓存上限 16MiB/512 项，单项 512KiB、5 分钟 TTL，活动引用受到保护；退出账号、换账号、实际删除文件会失效。移除消息中的附件关系不删除文件或其他分支的缩略图。

后端保存可索引的尺寸、位深、方向与动画元数据。来源别名按用户隔离，只指向当前策略下已知静态、正常方向、8bit 以内的 PNG/JPEG；权限、状态、有效期、硬限制及对象内容校验仍独立执行。用户配额事务锁与唯一来源键协调并发，首个规范成品成为该来源的文件身份。若上传请求最终复用了其他浏览器保存的成品，客户端使用服务器 fileID 读取预览，不显示自己的另一份编码。

普通、历史、临时、MCP 图片及图片编辑/蒙版共享服务器 `imageutil.Prepare`。合格静图直接使用原字节；旧图确需解码时采用 CatmullRom，保留透明度并处理方向。旧图解码每用户最多 1 个、全局最多 2 个，总估算工作集 256MiB；没有全站单条串行队列。标准 Go 解码器不能在单次 decode 内部中断，取消在排队/阶段边界生效。请求级缓存合并相同内容的工作，并在每次命中后继续执行实际渠道预算校验。

## HTTP 契约

- `GET /runtime/chat-file-policy` 的既有策略响应增加 `imageMaxDimension`、`imagePolicyVersion`。本节路由均相对于 `/api/v1`。
- `POST /files/image-reuse/lookup`：`{items:[{sourceSha256,sourceSizeBytes,imagePolicyVersion}]}`；返回对应 `file|null`、当前 `imagePolicyVersion` 和 `quota`。过期策略或无效来源为 miss，不披露其他用户内容。
- 上传 multipart 可附 `source_sha256`、`source_size_bytes`、`image_policy_version`。客户端来源哈希只是私有复用键，服务器独立计算成品哈希。
- 图片准备失败为 HTTP 400 / `file.image_processing_failed`；无法安全读取动画为 400 / `file.animation_unsupported`。HTTP 与 NDJSON 共用错误映射，包含文件名及当前/历史范围。
- `POST /messages/{id}/revisions`：`{content,fileIDs,expectedUpdatedAt,revisionID}`。`fileIDs` 必须是完整集合，允许 `[]`，不接受缺省/null；返回新消息及 `selectedLeafMessagePublicID`。稳定 UUID `revisionID` 支持响应丢失后的幂等重试；修改同一 ID 的负载会冲突。

## 编辑与分支

编辑草稿独立于主输入框，可保留、添加、移除、替换图片/文件，支持拖放、粘贴和预览。取消仅释放草稿拥有的预览资源；不会撤销原消息附件或删除上传文件。

附件集合发生变化时，“仅保存”建立新的用户消息分支，不调用模型；“保存并重新生成”沿既有生成分支流程发送最终集合。纯文字仅保存沿用既有 PATCH 行为。双空内容不可保存，纯附件消息允许保存；上传中禁用提交，失败保留草稿。保存事务验证归属、源版本、运行状态及全部文件，成功前不落部分修订。删除本草稿附件不会影响旧分支及其回答。

临时对话使用本次会话的分支快照，数组复制、File 共享，切换分支恢复相应历史；会话结束时统一释放。异步保存和上传完成后再次确认会话/账号范围，避免切换页面后把结果写入另一个对话。

本批另修复历史分页只加载尾段时忽略分支选择的问题；从已加载的最早祖先向选定子分支遍历。翻页采用同步锁与加载代际隔离，旧请求不能清除新请求的加载状态或覆盖新对话。

## 验证口径

本机 Chrome 157 / i7-11800H 的真实 Worker 路径，1536 最长边，十张混合 2K/4K JPEG 的一轮准备总耗时约 734ms（含 SHA，未含网络）；2K 稳态约 78–88ms，单张 4K 约 132–199ms，8K 约 430–577ms。同期存在构建/测试负载，首次 Worker 启动另外计入；这些是合成图片本机结果，不保证所有设备或素材每张低于 100ms。

真实浏览器另核对 EXIF 八方向与四角像素、透明 PNG、SDR PNG16、静态/动画 GIF、APNG/WebP；单元/事务回归覆盖来源复用、账号隔离、配额、取消、缓存、修订和分页竞态。PostgreSQL 多连接生产并发、真实手机/WebView codec、收费模型请求及线上全链路耗时需要部署后验证。SQLite 事务测试不能等同于 PostgreSQL 压测。本批不解释或宣称解决纯文字每条消息的 10–60 秒首响应等待。

Web 行为回归 128 项、生产构建及生成 API 契约一致性检查通过。生产打包的 JS Worker 已在 Chrome 实际执行 SHA、1536 缩放与编码；`out` 导出资源不作为 TypeScript 源码重复检查。编辑器真实交互覆盖取消、全删、双空拒绝、替换失败/成功/已有附件、上传中禁用、保存失败保留草稿、幂等重试与临时图片不上传，桌面和 390px 窄屏均检查过布局。

全仓前端架构检查仍报告工作区既有的未提交预览路由和 `upload-mime.ts` 断言，本批没有新增规则违例；后端全套检查中的 Windows POSIX 文件权限断言（0600/0644 被报告为 0666）不属于本批功能，未通过更改权限测试掩盖平台差异。
