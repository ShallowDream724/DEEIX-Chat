# 附件输入、上下文观测与原生工具

本页记录当前分支的运行规则；完整超限处理见 [输入策略](context-input-policy-plan.md)，后续方案见 [排期](FORK_ROADMAP.md)。部署仍需正常构建、发布，本地提交不会修改线上配置。

## 管理入口

附件与模型输入设置位于**管理员 → 文件与检索**；MCP 图片处理专属设置位于**管理员 → 工具 → MCP 设置**。

| 分组 | 设置与作用 |
| --- | --- |
| 上传限制 | 临时会话请求附件总数、默认单文件大小、图像/文档/音频/视频分类大小、用户累计存储额度。分类为空则继承默认，填写后使用分类值 |
| 图片处理 | 发送图片最大边长（默认 1024px，0 表示不缩放）与单张生成图片保存上限 |
| 模型输入预算 | 系统默认及每渠道覆盖：单消息附件数、完整请求字节数、图片数量/单张/合计、原生文件数量/合计、PDF 单个/合计/页数、原生音视频合计 |
| 内容提取 | 提取引擎、服务连接、OCR 等业务设置；读取保护保留后端配置 |
| 全文注入 | 单文件提取文字大小和 token 预算。PDF 页数不再作为全文门槛，也不限制解析器只读前 N 页 |

MCP 图片处理器的输入总大小、单图识别结果字符数、合计识别结果字符数沿用工具页面设置，只作用于选用该处理器的请求。识别文字的现有截短策略与本文档的完整文档提取规则独立，不限制模型原生视觉。

提取/OCR 源文件及响应、MinerU 归档及文本、临时会话基础 JSON、处理结果缓存的容量属于实现保护，保留既有配置，不在日常管理页逐项展示。读取保护超限会失败；完整解析结果超过全文预算时，可按已启用且可用的 RAG 路径处理，否则明确拒绝，不静默遗漏或截取正文。

**管理员 → 上游渠道 → 编辑渠道 → 输入限制**只展示预算摘要及跳转入口。预算在文件与检索统一编辑，没有重复的模型级字节预算表单。模型能力仍决定输入类型、上下文窗口等条件。

页面统一显示十进制 MB（1,000,000 字节），已有字节值精确换算显示，不因修改显示单位而重写。仅未编辑的旧默认种子值可以迁移到十进制默认；管理员明确保存的值保持不变。输入框留空显示实际继承值，0 表示该项不限额；缓存、边长等具有不同含义的 0 分别显示“禁用”“不缩放”。

配置范围、渠道选择和继承说明放在同一配置区域。范围仅有系统默认和指定渠道，不再区分渠道内的协议。单消息附件数纳入同一预算设置，旧全局值启动时迁移，不再提供两个编辑入口。

## 预算解析与发送

`shared/inputlimits` 负责默认值、配置校验和继承。`file.input_limits` 仅保存 `defaults` 和以渠道 ID 为键的 `upstreams`；依次应用内置默认、系统设置、渠道覆盖。省略/null 继承，显式 0 关闭该项运营限制。供应商硬限制由独立的 ProviderRules 检查，不因管理员填写 0 而失效；兼容地址不自动套用官方地址规则。

| 系统默认项 | 值 |
| --- | --- |
| 单消息附件数 | 10 |
| 最终编码请求体 | 100 MB |
| 图片数量 / 处理后单张 / 合计 | 20 / 5 MB / 20 MB |
| 原生文件数量 / 合计 | 10 / 50 MB |
| PDF 单份 / 合计 / 合计页数 | 50 MB / 50 MB / 200 页 |
| 原生音视频合计 | 50 MB |
| 单文件解析全文保护 | 2 MB / 256,000 tokens |

当前实现的官方服务约束与上表分开：OpenAI 官方 PDF 单份小于 50 MB、合计 50 MB；Gemini GenerateContent 单 PDF 50 MB；Anthropic 按已知模型窗口执行图片、PDF 页数及图像编码限制。各图像/视频适配器继续执行自己的参考图数量和输入结构约束。运营默认值不宣称任意渠道都能接收该容量，也不为模型新增输入能力。

`imageSingleBytes` 与 `imageBytes` 统计发送图片副本、Base64 之前的字节；原生文件统计原件；`requestBytes` 统计最终编码的 JSON 或 multipart，包含历史、附件、文字和工具。同一内容实际出现多次就重复计入传输预算。上传原件上限和用户存储配额分别执行。

完整上下文按实际渠道检查，超限不自动取最新图片/文件，不静默降级原生文件。读取有界并检查完整性，最终序列化后再次校验；流式、非流式、临时会话、工具续问与路由切换共用边界。错误保持已有错误码，并携带安全的维度、实际值、上限及必要的文件名/当前或历史范围。

预检读取已知元数据，不重复提取或调用付费模型。多个候选渠道时只提前阻断共同确认的问题，实际发送仍按最终路由复核。系统/渠道数量与大小提示采用“所选渠道”，模型能力和上下文采用“所选模型”。已上传原件不会因发送失败而删除，可继续在用户文件中复用。

原生就绪不依赖后台文字提取是否完成或成功。启用 PDF 页数预算而记录缺少页数时，预检与发送共用独立页树探测，不做 OCR；已知字节/数量超限先拒绝，单次预检/发送中成功和失败的探测均复用。后台文字提取失败或为空仍保存已知原件页数，不能把它冒充已提取页数。Chat01 的音频、视频和通用附件同样不因解析失败被挡住；白名单、权限、大小、数量和存储规则仍执行。无法确认 PDF 页数时不绕过已配置的页数预算。

## 图片处理与缓存

本批保留现有最长边缩放及编码算法，不按文件MB大小触发优化。存储原件不变，只处理发送副本；0在普通、历史、临时及图片工具路径含义一致。缓存键包含源身份和处理参数，修改尺寸不会误用旧结果。缓存淘汰只影响重复处理成本，不删除分支附件。图片处理缓存的数量与容量属于实现配置，保留既有配置兼容性，不在管理员设置页面展示。

单次发送的原生读取缓存、处理后图片缓存、供应商prompt cache、OpenAI `previous_response_id`是不同机制。Gemini原生PDF/音视频继续采用inlineData；没有新增Files API或自动创建供应商显式缓存。续接不适用时重新提供完整有效上下文与原件。

## 分支与token观测

滚动摘要替代聊天文字，不替代附件引用。附件从当前叶节点的祖先路径收集，之后重新检查所有权、删除状态、实际模型能力和预算。摘要之前仍有效的文件会放到保留的用户消息中；不会收集兄弟分支或未来消息。

每次可靠响应保存的是**整次模型输入观测**，不冒称某个PDF独立token。保存哈希与计数，不保存提示词、媒体字节或密钥。观测要求实际路由/模型、相关参数、工具、稳定系统内容、文件身份和内容匹配；只有当前祖先路径上的观测可用。

适用时以已返回的实际输入为基线，只估算此后保留文字的增减；下一次响应重新校准。编辑中间消息采用该消息之前的祖先观测，排除旧版本后续消息。首次或观测失效时使用估算。发送前硬预算、工具续问和响应后的压缩判断采用相同口径。关闭自动压缩时停止超限请求，不裁掉旧历史继续。临时会话共享判断，并使用按用户、会话、路由及祖先指纹隔离的有界观测缓存；最多 1,024 条、30 分钟过期，未命中则保守估算。

工具请求的输入10k→11k→12k，最新上下文为12k；账单仍可以累计33k。缓存读只按规范化输入语义还原一次，不重复添加。摘要trace中的文字token变化只描述文字摘要，不表示PDF等附件被压缩成摘要大小。

## 原生工具与计费

OpenAI工具详情保存并展示已返回的输入、代码/命令/查询、输出与错误，支持独立Shell call/output关联、流式占位合并和结束结果更新。查看详情只读取保存结果，不重跑工具。生成产物沿用文件存储边界，不把图片Base64塞进详情。

DeepSeek搜索与读取分别使用`deepseek.tool_search`、`deepseek.tool_fetch`身份，计量来自`usage.server_tool_use`成功次数；不按web_search_call项数猜测。Google搜索按实际模型代际与返回查询记录计量，grounding来源和引用独立保留。

DeepSeek 的请求只声明一个 Responses `web_search`；fetch 是该工具内部的独立计量项，不能作为 `web_fetch` 请求工具单独发送。旧 search/fetch 配置保存时合并启用和默认状态，保留 search 参数；Chat Completions 不派发也不预留这两项。若多个工具声明共享无法区分的计量别名但对应不同价格身份，则在派发前排除冲突声明，计费授权使用同一结果，不按声明顺序猜测归属。

请求授权冻结工具价目，实际启用工具以明确身份参与预留和结算；过程中改价不追溯本轮。免费token模型调用收费原生工具仍需对应预算。至少预留每个选中工具一次操作，最终按实际成功操作计费；供应商自主多次操作且无次数上界时，最终费用可能超过这一最低预留。沿用已有RefNo与幂等结算，不将未获准的同名供应商工具代入价目。

## 后续边界

本批不新增用户上下文进度条、图片按MB优化、新缩放算法、长图切块、子块聚合管理、OpenAI detail或Gemini新的分辨率参数。分辨率与token调研见[调研记录](image-resolution-token-research.md)。默认1024保留，管理员可以调整；不存在已经证实的跨模型“1024永远足够”结论。

## 本地验收

已覆盖上传分类替代/继承、完整请求边界、JSON/multipart无网络拒绝、原件读取完整性、0不缩放、缓存参数隔离、同名文件的实际内容追踪、第三轮摘要后回到第二轮分支、编辑中间消息的祖先观测、实测PDF与本地工具续问、末次上下文和累计账单分离、原生工具成功/失败/取消及价格冻结。测试网关会检查实际`GenerateInput`中的附件字节；没有执行付费上游模型调用。

本轮共享预算、设置、会话、压缩、提取、embedding、内置 PDF 和 HTTP 会话包测试，以及 Web 类型检查和前后端构建通过。接口契约由 Swagger 重新生成。真实 21 页 PDF 回归确认临时请求包含最后一页；全文超限时不调用上游。真实组件预览覆盖桌面、390px 窄屏和浅深主题。未重复运行完整仓库测试；此前 Windows 的 POSIX 文件权限断言差异仍独立保留。

本地界面已核对单位、输入框间距与预算分组；页面统一MB，保留既有实际字节值。测试库、存储和账号独立于线上环境。供应商真实渠道的可读性、搜索返回与计费账单仍需要配置该渠道后的实际验收，不能由模拟响应证明线上可用性。

生成文件列表复用现有附件组件：文件名打开预览，右侧独立下载按钮，已知实际大小显示在按钮左侧；正文下载链接补充已知大小。当前下载仍使用原有 Blob 链路，大文件流式下载及一次超配额接收仍属于后续工作。
