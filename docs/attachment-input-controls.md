# 附件输入、上下文观测与原生工具

本页记录本批代码的运行规则；历史调查和后续方案见 [排期](FORK_ROADMAP.md)。部署仍需正常构建、发布，本地提交不会修改线上配置。

## 管理入口

所有附件运营设置集中在**管理员 → 文件与检索**，不新增“高级”总分组。

| 分组 | 设置与作用 |
| --- | --- |
| 上传限制 | 单条消息附件数量、默认单文件大小、图像/文档/音频/视频分类大小、用户累计存储额度。分类为空则继承默认，填写后使用分类值，不再暗中与默认值取小值 |
| 图片处理 | 发送图片最大边长，默认1024px；0表示本站不缩放，可设1568/2048/3072。处理后图片缓存项数、缓存字节容量 |
| 模型输入预算 | 默认规则、指定上游的通用值、指定上游的协议/任务值。完整请求字节数、图片数量/单张/合计、原生文件数量/合计、PDF单个/合计/页数、非PDF原生音视频合计 |
| 临时会话附件 | 临时附件数量、基础JSON请求大小；multipart容量按基础请求和允许附件推导 |
| 图片工具 | 图片工具处理后输入字节、单图分析文字、合计分析文字 |
| 生成文件 | 生成图片保存大小；不是上传图片压缩目标 |
| 内容提取 | 提取源文件、提取响应、OCR源文件、OCR响应大小；MinerU归档与解压文字分别设置 |
| 全文注入 | 单文件提取文字大小、单文件token、单个PDF页数。Word/PPT/其他文档同样受前两项约束，未伪造统一页数 |

**管理员 → 上游渠道 → 编辑渠道 → 输入限制**只展示预算摘要及跳转入口。预算只在文件与检索编辑，没有重复的模型级字节预算表单。模型能力仍决定输入类型、上下文窗口等条件。

页面统一显示十进制MB（1,000,000字节）。旧设置原先按1,048,576字节换算，本批按实际保存的字节精确换算显示；例如52,428,800字节显示52.4288MB，未编辑保存时不会改变实际额度。默认值、用户累计额度和已有配置均不因显示单位变化被重写。

输入框不重复展示所填上限；留空时以灰字显示实际继承值。上传分类取当前默认单文件大小，预算按系统默认、默认规则、上游通用、协议特例的对应父层解析；系统默认由设置API单独返回，不把管理员已修改的值误当系统默认。预算区在范围与渠道选择下方只说明一次：“留空时使用默认上限；设置为0表示不限制。”单位放在框内，与既有设置一致。已保存的0在未编辑时显示灰字“不限制”，聚焦后显示0；缓存、图片边长等具有不同含义的0分别显示“禁用”“不缩放”。预算来源与供应商限制记录于本页，管理页面不展示调查日期或长篇文档说明。

## 预算解析与发送

`shared/inputlimits`负责默认值、配置校验和继承。`file.input_limits`保存JSON，依次应用：协议/服务默认规则 → 默认规则修改 → 上游通用修改 → 上游协议/任务修改。留空继承，显式0关闭额外运营限制；已确认的供应商硬限制仍单独执行。第三方兼容地址不会因为模型名相同而套用官方地址规则。

| 默认规则 | 完整请求 | 图片数量 | 原生文件规则（不包含普通图片） |
| --- | --- | --- | --- |
| OpenAI官方聊天 | 512MB | 1500 | 原生合计50MB；单PDF小于50MB、PDF合计50MB；非PDF原生输入14MiB |
| Gemini GenerateContent | 100MB | 不额外限数量 | 单PDF50MB、PDF合计200页；取消旧74.2MB原件推导总额，以最终编码请求检查为准 |
| Gemini Interactions | 100MB | 不额外限数量 | 预算配置不表示新增PDF/音视频原生支持 |
| Anthropic官方 | 128MB | 默认600；200k窗口或未知窗口时100 | PDF默认600页；实际窗口不足1M或未知时100页；另检查单图Base64大小和8000px边长 |
| OpenRouter / 其他兼容协议 | 100MB运营保护 | 不额外限数量 | 原生合计14MiB；单PDF与PDF合计8MiB、100页；非PDF14MiB；取消旧5文件统一数量限制 |
| xAI图片编辑 / 视频生成 | 100MB运营保护 | 3 / 1 | 保留适配器的真实输入结构限制 |
| OpenRouter图片任务 | 100MB运营保护 | 16 | 保留适配器的参考图片数量限制 |

上述默认值不宣称任意渠道都能接收该容量。尤其兼容渠道100MB属于本站运营保护；管理员可以给特定渠道填写其实际限额。Gemini不同文档/端点的容量口径仍需实际渠道验证。

`imageSingleBytes`与`imageBytes`统计准备发送的图片副本、Base64之前的字节；原生文件字节统计原件；`requestBytes`统计最终编码后的整个JSON或multipart，包含历史、图片、文件、文字、工具和结构开销。同一内容实际出现多次就重复计入传输预算。它们与用户存储配额各自独立。

图片和原生文件的读取均有界并检查完整性，不接受截断前缀。最终序列化后、HTTP发出前再次校验请求；流式、非流式与路由切换共用边界。超限保持已有`file.too_large`错误码，附带安全的维度、实际值与上限，前端显示具体原因。

历史图片不再无说明截为最近10张，也不再独立套隐藏20MiB。按实际渠道检查当前与历史输入。内部`SourceFileIDs`用于核对最终保留的内容，绝不发给供应商；文件同名不合并，未发送内容不能显示成已使用。

## 图片处理与缓存

本批保留现有最长边缩放及编码算法，不按文件MB大小触发优化。存储原件不变，只处理发送副本；0在普通、历史、临时及图片工具路径含义一致。缓存键包含源身份和处理参数，修改尺寸不会误用旧结果。缓存淘汰只影响重复处理成本，不删除分支附件。

单次发送的原生读取缓存、处理后图片缓存、供应商prompt cache、OpenAI `previous_response_id`是不同机制。Gemini原生PDF/音视频继续采用inlineData；没有新增Files API或自动创建供应商显式缓存。续接不适用时重新提供完整有效上下文与原件。

## 分支与token观测

滚动摘要替代聊天文字，不替代附件引用。附件从当前叶节点的祖先路径收集，之后重新检查所有权、删除状态、实际模型能力和预算。摘要之前仍有效的文件会放到保留的用户消息中；不会收集兄弟分支或未来消息。

每次可靠响应保存的是**整次模型输入观测**，不冒称某个PDF独立token。保存哈希与计数，不保存提示词、媒体字节或密钥。观测要求实际路由/模型、相关参数、工具、稳定系统内容、文件身份和内容匹配；只有当前祖先路径上的观测可用。

适用时以已返回的实际输入为基线，只估算此后保留文字的增减；下一次响应重新校准。编辑中间消息采用该消息之前的祖先观测，排除旧版本后续消息。首次或观测失效时使用估算。发送前硬预算、工具续问和响应后的压缩判断采用相同口径。

工具请求的输入10k→11k→12k，最新上下文为12k；账单仍可以累计33k。缓存读只按规范化输入语义还原一次，不重复添加。摘要trace中的文字token变化只描述文字摘要，不表示PDF等附件被压缩成摘要大小。

## 原生工具与计费

OpenAI工具详情保存并展示已返回的输入、代码/命令/查询、输出与错误，支持独立Shell call/output关联、流式占位合并和结束结果更新。查看详情只读取保存结果，不重跑工具。生成产物沿用文件存储边界，不把图片Base64塞进详情。

DeepSeek搜索与读取分别使用`deepseek.tool_search`、`deepseek.tool_fetch`身份，计量来自`usage.server_tool_use`成功次数；不按web_search_call项数猜测。Google搜索按实际模型代际与返回查询记录计量，grounding来源和引用独立保留。

请求授权冻结工具价目，实际启用工具以明确身份参与预留和结算；过程中改价不追溯本轮。免费token模型调用收费原生工具仍需对应预算。至少预留每个选中工具一次操作，最终按实际成功操作计费；供应商自主多次操作且无次数上界时，最终费用可能超过这一最低预留。沿用已有RefNo与幂等结算，不将未获准的同名供应商工具代入价目。

## 后续边界

本批不新增用户上下文进度条、图片按MB优化、新缩放算法、长图切块、子块聚合管理、OpenAI detail或Gemini新的分辨率参数。分辨率与token调研见[调研记录](image-resolution-token-research.md)。默认1024保留，管理员可以调整；不存在已经证实的跨模型“1024永远足够”结论。

## 本地验收

已覆盖上传分类替代/继承、完整请求边界、JSON/multipart无网络拒绝、原件读取完整性、0不缩放、缓存参数隔离、同名文件的实际内容追踪、第三轮摘要后回到第二轮分支、编辑中间消息的祖先观测、实测PDF与本地工具续问、末次上下文和累计账单分离、原生工具成功/失败/取消及价格冻结。测试网关会检查实际`GenerateInput`中的附件字节；没有执行付费上游模型调用。

Web类型检查、lint、23条架构检查、生产构建及Swagger/TypeScript契约一致性检查通过。完整Go测试中，本批相关包通过；Windows上两项原有POSIX文件权限断言失败：`infra/config`期望0600、`infra/persistence/filecache`期望0644，实际均为0666。未为掩盖平台差异修改这些权限测试。

本地界面已核对单位、输入框间距与预算分组；页面统一MB，保留既有实际字节值。测试库、存储和账号独立于线上环境。供应商真实渠道的可读性、搜索返回与计费账单仍需要配置该渠道后的实际验收，不能由模拟响应证明线上可用性。
