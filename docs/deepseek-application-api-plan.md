# DeepSeek 应用 API 接入方案

更新：2026-11-14。状态：方案已收敛如下，尚未实现；本记录不代表功能已发布。

## 本轮范围

- Flash 新版联网工具、URL 阅读与 Files 接入，统一复用既有多模态、文件权限、附件引用、缓存、预算及分支处理。能力按供应商、协议、实际模型配置声明，为后续 Pro 多模态扩展保留边界；本批不新增 Pro Files 支持。
- 搜索、URL 阅读默认开启，不让用户额外选择搜索深度。搜索跟随最终规范化后的 thinking 状态：off 普通，其余启用思考时使用深度搜索；DeepSeek 的 medium 官方映射为 high。不能把本地某个努力档位随意解释成普通搜索。
- 深度搜索不独立执行 read_url 时，对用户明确给出的 URL 按需要采用 Fetch 适配；按轮次去重，不对没有 URL 的普通消息新增抓取等待。计量按上游真实成功用量，补齐图片搜索及供应商协议字段。
- Flash 的 PDF、Word、PPT 使用 rich_layout_recognition；识别文字和检测出的图片进入模型，不把文字模式当多模态。Excel 的路径通过开发阶段一次性对照实验选择，比较多工作表、合并单元格、公式缓存值、日期与图表内容以及延迟；不在用户每次发送前并行运行两套解析。结果决定默认路径，失败回退也必须有明确触发条件。
- 独立 DeepSeek OCR 暂不替换现有 MinerU；Files 的图文模式与单独 OCR 文本接口分开。
- 手机端模型列表计费按钮改为触屏可点击的详情入口，复用已有价格内容与组件，保护列表滚动、分组、焦点和模型选择。

## 语音输入

- 用户追加指定 [VoiceKey](https://github.com/J3n5en/voicekey) 中的微信、豆包等输入法渠道；ASR 方案不再限于 DeepSeek，优先纳入豆包输入法和微信输入法的流式适配，保留浏览器识别及 DeepSeek 完整音频转写选项。其他 VoiceKey 渠道按各自协议与登录依赖逐一核验，不把它们与同厂商商业 ASR API 混为一项。当前仍为研究/方案阶段，源码核验见 [VoiceKey 流式识别核验](voicekey-streaming-audit.md)。
- 供应商适配器明确声明流式能力、格式、时长/大小限制，公共层负责录音会话、草稿写入、提醒和取消。浏览器采音与端侧处理持续输出有界音频帧，后端适配供应商协议并回传本段临时/最终文字；不等完整录音后才建立流式通路。供应商身份与连接按用户/会话隔离，避免将桌面程序单用户的全局状态直接移入多用户服务。
- DeepSeek ASR 当前明确不支持流式识别：提交完整音频后返回完整文本，单段最长 120 秒、8 MiB，接收 PCM16 WAV 或 Ogg Opus。不能用频繁切片并重复提交伪装原生流式。录制期间显示录音状态，结束后显示识别状态。
- 每次录音的有效上限由本站配置和已确认的渠道硬上限共同决定；接近上限前 10 秒开始倒计时，到点结束录音并请求本段定稿，不能因浏览器自动重启识别而重置整段时限。按实际采样时长约束音频，不能只依赖后台可能被节流的 UI 定时器；DeepSeek 的 120 秒不能套用为微信、豆包硬上限，握手/收包/定稿超时也不等于录音时长上限。
- 有草稿时仍能继续点击语音输入。新段追加到已有内容；流式渠道的临时结果只更新当前段，最终结果幂等提交，不能整框覆盖已有段落或用户编辑。录音停止不能丢最后一段结果。
- 每段绑定用户、会话/临时草稿与识别会话身份；切对话、重新录音、取消、发送和迟到响应不允许把结果写入别的草稿或复活已发送内容。音频缓冲有界，停止/取消后释放麦克风和处理资源；识别失败保留原草稿。
- 现有代码以草稿快照加本段结果写回，不能直接断言所有重复录音都会覆盖。已确认有内容后主按钮变成发送按钮，且未实现录音时限/提醒；覆盖反馈需用连续口述、停止尾包、切会话与草稿更新回归定位。

## 朗读回复

- 首批以可扩展语音服务接入 DeepSeek TTS，其他供应商后置。用户聊天设置提供语音识别来源、自动朗读回复（默认关闭）与已配置音色；文案、布局沿用项目既有设置风格。后台负责渠道凭据与费率，前端不持有渠道密钥。
- 自动朗读只响应当前会话中新回复的成功完成事件；刷新、重连、历史渲染、切分支、重复完成事件不重复触发。保留手动朗读与暂停/重播入口。
- DeepSeek 支持 HTTP 整段文本输入、音频流式输出，也支持 WebSocket 文本/音频流。当前“回复完成后朗读”优先走完整正文加流式音频，不要求等待全部音频生成后才播放。
- 同一用户、规范化朗读文本、渠道/模型、音色、格式及版本复用合成结果，合并并发请求；合成去重与播放去重分开。失败/中断的部分音频不能伪装完整缓存，结果不明时不盲目重新扣费合成。
- 单次最多 10,000 个计费字符（汉字计 2）、64 KiB 文本请求，输出最多 30 分钟音频。长回复按句段划分并受总预算约束，不静默截尾或无界预合成；按需读取、有限预取，缓存有体积/生命周期限制，不预加载全部历史音频。浏览器拒绝自动播放时允许手动播放同一结果，不重新合成。
- ASR 使用音频时长计量，TTS 使用供应商定义的字符计量；价格快照、幂等结算与缓存命中复用现有计费边界，不冒充模型 token 用量。

## 开发验证

- 先以模拟结果验证追加文本、倒计时、最大时长、尾包、乱序响应、会话切换、重复事件、取消失败、后台恢复和资源释放，再做少量真实请求验证协议、格式和费用。
- Excel 的对照只在开发阶段运行，使用合成样本，记录正确性和耗时后选择默认策略。
- 用户已提供并持续授权专用 DeepSeek 开发测试凭据；密钥与本机授权记录保存在仓库外。本轮未发起付费 API 请求。
