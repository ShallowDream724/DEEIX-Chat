# DeepSeek 应用 API 接入方案

更新：2026-11-14。状态：本批已实现并通过本地集成验收，尚未发布镜像。实际接口见 [语音 API](speech-api.md)、[前端语音](speech-frontend.md)、[语音设置](speech-settings.md) 和 [附件输入](attachment-input-controls.md)。开发实验见 [本批验证记录](deepseek-speech-validation-20261114.md)。

## 本轮范围

- Flash 新版联网工具、URL 阅读与 Files 接入，统一复用既有多模态、文件权限、附件引用、缓存、预算及分支处理。能力按供应商、协议、实际模型配置声明，为后续 Pro 多模态扩展保留边界；本批不新增 Pro Files 支持。
- 搜索、URL 阅读默认开启，不让用户额外选择搜索深度。搜索跟随最终规范化后的 thinking 状态：off 普通，其余启用思考时使用深度搜索；DeepSeek 的 medium 官方映射为 high。不能把本地某个努力档位随意解释成普通搜索。
- 深度搜索不独立执行 read_url 时，对用户明确给出的 URL 按需要采用 Fetch 适配；按轮次去重，不对没有 URL 的普通消息新增抓取等待。计量按上游真实成功用量，补齐图片搜索及供应商协议字段。
- Flash 的 PDF、Word、PPT 使用 rich_layout_recognition；识别文字和检测出的图片进入模型，不把文字模式当多模态。官方不保证裁出每张图片。Excel 经开发阶段对照后保留本地解析默认；不在用户每次发送前并行运行两套解析。Files 解析费用本批由平台承担，Office 未知页数单独记录，不伪造页数扣费。
- 独立 DeepSeek OCR 暂不替换现有 MinerU；Files 的图文模式与单独 OCR 文本接口分开。
- 手机端模型列表计费按钮改为触屏可点击的详情入口，复用已有价格内容与组件，保护列表滚动、分组、焦点和模型选择。

## 语音输入

- 用户追加指定 [VoiceKey](https://github.com/J3n5en/voicekey) 中的微信、豆包等输入法渠道；本批已接入豆包输入法和微信输入法流式适配，保留浏览器识别及 DeepSeek 完整音频转写选项。其他 VoiceKey 渠道按各自协议与登录依赖逐一核验，不把它们与同厂商商业 ASR API 混为一项。源码核验见 [VoiceKey 流式识别核验](voicekey-streaming-audit.md)。
- 供应商适配器明确声明流式能力、格式、时长/大小限制，公共层负责录音会话、草稿写入、提醒和取消。浏览器采音与端侧处理持续输出有界音频帧，后端适配供应商协议并回传本段临时/最终文字；不等完整录音后才建立流式通路。供应商身份与连接按用户/会话隔离，避免将桌面程序单用户的全局状态直接移入多用户服务。
- DeepSeek ASR 当前明确不支持流式识别：提交完整音频后返回完整文本，单段最长 120 秒、8 MiB，接收 PCM16 WAV 或 Ogg Opus。不能用频繁切片并重复提交伪装原生流式。录制期间显示录音状态，结束后显示识别状态。
- 每次录音的有效上限由本站配置和已确认的渠道硬上限共同决定；接近上限前 10 秒开始倒计时，到点结束录音并请求本段定稿，不能因浏览器自动重启识别而重置整段时限。按实际采样时长约束音频，不能只依赖后台可能被节流的 UI 定时器；DeepSeek 的 120 秒不能套用为微信、豆包硬上限，握手/收包/定稿超时也不等于录音时长上限。
- 有草稿时仍能继续点击语音输入。新段追加到已有内容；流式渠道的临时结果只更新当前段，最终结果幂等提交，不能整框覆盖已有段落或用户编辑。录音停止不能丢最后一段结果。
- 每段绑定用户、会话/临时草稿与识别会话身份；切对话、重新录音、取消、发送和迟到响应不允许把结果写入别的草稿或复活已发送内容。音频缓冲有界，停止/取消后释放麦克风和处理资源；识别失败保留原草稿。
- 语音入口现已独立于发送按钮；有内容时仍可继续录音。本段编辑追踪、时限提醒、停止等待定稿和切会话隔离由统一录音会话管理。

## 朗读回复

- 首批以可扩展语音服务接入 DeepSeek TTS，其他供应商后置。用户聊天设置提供语音识别来源、自动朗读回复（默认关闭）与已配置音色；文案、布局沿用项目既有设置风格。后台负责渠道凭据与费率，前端不持有渠道密钥。
- 自动朗读只响应当前会话中新回复的成功完成事件；刷新、重连、历史渲染、切分支、重复完成事件不重复触发。保留手动朗读与暂停/重播入口。
- DeepSeek 支持 HTTP 整段文本输入、音频流式输出，也支持 WebSocket 文本/音频流。当前“回复完成后朗读”优先走完整正文加流式音频，不要求等待全部音频生成后才播放。
- 同一用户、规范化朗读文本、渠道/模型、音色、格式及版本复用合成结果，合并并发请求；合成去重与播放去重分开。失败/中断的部分音频不能伪装完整缓存，结果不明时不盲目重新扣费合成。
- 单次最多 10,000 个计费字符（汉字计 2）、64 KiB 文本请求，输出最多 30 分钟音频。长回复按句段划分并受总预算约束，不静默截尾或无界预合成；按需读取、有限预取，缓存有体积/生命周期限制，不预加载全部历史音频。浏览器拒绝自动播放时允许手动播放同一结果，不重新合成。
- ASR 使用音频时长计量，TTS 使用供应商定义的字符计量；价格快照、幂等结算与缓存命中复用现有计费边界，不冒充模型 token 用量。

## 语音输入与媒体播放交互（用户截图补充）

- 语音入口及设置文案统一使用“语音输入”，识别渠道作为具体选项。按用户提供的 ChatGPT 录音截图组织输入栏：上方保留草稿和实时识别文字，下方显示完整录音操作行，包括取消、横向波形、计时/剩余时间、停止和发送。桌面、平板、手机共享结构，小屏优先保证按钮触控区，波形弹性收缩；不只靠右下角小图标表达正在录音。
- 取消只撤销当前录音段，保护开始前已有文字；停止结束录音并完成本段识别，文字保留可编辑；录音中发送先停止、等待本段最终结果，再仅发送一次。识别失败不自动发送不完整文字，已有内容和可用识别结果保留供编辑。DeepSeek 停录后的转写阶段明确显示识别状态，波形不继续假装收音。
- 用户主动开始下一段录音时默认另起一行，已有换行不重复添加；一次录音内部的临时修订、分句、协议重连不插入段落。保留上游已有的中英文标点，避免机械追加句号导致重复标点或改变内容；英文单词边界按需保留空格。最终文字不能覆盖此前段落或用户在等待期间的编辑。
- 所有已知且可预期的录音/会话时长上限，包括本站配置，统一在剩余 10 秒时显示倒计时，到点自动结束本段并定稿；有效剩余不足 10 秒时立即显示实际剩余值。不把收包超时或静音自动结束阈值伪称为录音总长限制；突发断线即时提示并保留文字。微信、豆包的上游总长仍待实测，不宣称无限时长，也不套用 DeepSeek 的 120 秒。
- 左侧短条是消息位置导航，右侧是当前回复的标题/章节导航，不是分支切换。两者均为上游既有：位置导航历史 `59ee3dbd`、标题导航引入 `d194e227` 均包含于 `origin/dev`；当前实现分别为 `chat-message-position-rail.tsx` 与 `chat-response-outline-rail.tsx`。它们继续承担定位功能，在语音输入或本站音频、视频声音、TTS 播放时增加轻量音量反馈。只动画实际可见的条目，两条时也只用这两条；不补造条数，不移动点击区域，不改变正文布局。
- 律动限定在导航留白和既有裁剪边界内，采用小幅长度/透明度变化；当前项辨识不被掩盖，悬停或键盘定位时降低动效，菜单和正文不被覆盖。右侧文件栏展开后按实际空间显示，不挤压正文。手机端沿用隐藏侧栏导航的规则，仅输入栏波形提供清楚的录音反馈。
- 建立共享的音频活动边界，区分录音、普通音频、视频声音与 TTS；可采样时由真实音量驱动，静音/暂停/结束后归静，静音视频不持续伪造声波。录音优先，开始语音输入暂停本站当前播放，避免把回放识别进去；录音期间不自动朗读新回复，结束后不擅自恢复播放。
- 采集/播放生命周期与波形显示分离。现有 `LiveWaveform` 自行申请麦克风并创建 AudioContext，不能直接给输入栏和两条侧栏各挂一份。自主管理的语音渠道共用一次录音采集和幅度分析；显示层只消费数据。浏览器原生识别若无法共享音轨或提供音量，则采用明确录音状态，不能仅为装饰再开启重复采集。
- 同一媒体元素只建立一套分析连接，波形与两侧导航共享数据；无可分析音轨或跨源资源不能安全接入分析时保留正常播放，不让可视化破坏声音。预分配小缓冲、绘制频率以约 24–30 Hz 为目标，不在音量帧上更新整段草稿或消息列表，不反复扫描历史。无活动、页面隐藏和组件卸载时停止相应绘制并释放资源，遵从减少动态效果偏好。
- 保留上传音视频的右侧预览模式及独立滚动，正文翻动时播放控制仍留在预览栏。音频初始即显示明确的播放按钮，不依赖 hover；播放/暂停、加载和失败状态完整，触屏与键盘可操作。视频已由 `PreviewMedia` 的原生 video 元素承载，补充加载/浏览器不支持格式的明确提示和下载入口，不假定所有可上传容器都可播放，也不新增默认服务器转码。
- 播放器关闭、切文件或退出时显式停止旧媒体并解除活动注册，复用既有对象 URL 管理，避免隐藏播放和悬挂动画。只新增必要的活动/控制接口，不将播放器、聊天草稿与导航职责耦合在一个组件。
- 音色由供应商适配器提供可选列表，普通用户不手填 voice_id。DeepSeek 当前公开音色为“海星”（stella）与“暗潮”（tide）；列表先以官方能力目录提供，未来供应商有查询接口时由后端缓存更新。打开音色列表或修改选择不自动付费合成，旧历史音频也不批量重建。

## 开发验证

- 先以模拟结果验证追加文本、倒计时、最大时长、尾包、乱序响应、会话切换、重复事件、取消失败、后台恢复和资源释放，再做少量真实请求验证协议、格式和费用。
- Excel 的对照只在开发阶段运行，使用合成样本，记录正确性和耗时后选择默认策略。
- 交互验收覆盖桌面/平板/手机、仅两条导航/长历史、录音与播放互斥、静音视频、右栏开关、取消/停止/发送/最后 10 秒、连续多段及中英文混合。波形活动不应触发消息列表逐帧重渲染，关闭后确认麦克风、分析节点、动画与对象 URL 按所属生命周期释放。
- 用户已提供并持续授权专用 DeepSeek 开发测试凭据；密钥与本机授权记录保存在仓库外。已进行少量合成样本的真实 API 实验，预算不超过 1 元，实际记录见本批验证记录。
