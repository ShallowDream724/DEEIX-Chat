- 图片编辑应用入口最多 16 张，OpenRouter Images 同为 16 张，xAI 图片编辑进一步限 3 张；视频生成参考图最多 1 张。编辑图像单张最多 67,108,864 像素；读取单图上限取上传上限与 50 MiB 的较大者。以上数量/像素值无管理入口；生成图片输出单张 50 MiB 是另一项写死的输出保护，不能误当输入预算。
- 图片 MCP 分析路径另有处理后图片合计 20 MiB、单图分析文本 6,000 字符和总分析文本 16,000 字符上限；准备后的历史图片缓存最多 64 项 / 64 MiB。这些为内部常量，缓存淘汰不应代表模型上下文删除文件。

- 20 MiB 历史图片预算不包含 PDF/音视频，也不包含普通会话本轮图片。它们分别合格后，组合请求仍可能超过供应商 payload 上限；Base64 通常再增加约三分之一体积。Gemini 最终校验能阻止超额请求发出，但预检和规划尚不能提前一致解释；其他已查协议还有缺口。
- 待确认的实施边界：站点上传与存储政策、实际渠道/模型输入限制、最终请求传输限制分别有明确职责，由同一解析结果供预检、规划、发送与 trace 使用。供应商限制按协议和实际渠道选用，管理员在渠道或绑定上可覆盖运营限制；Chat01 的 10 图上限只属于其渠道，不按模型展示名或 OpenAI 兼容协议扩大到其他供应商。
- 管理员可配置请求图片数/必要的运营字节限额，提供继承供应商规则的默认行为；供应商按整个请求限定的图数须合计本轮与历史，不能各给一份。模型 token 容量、图片张数、原件大小和编码后 payload 分别检查，不能互相代替。
- 上传分类设置按“有分类值则使用分类值，否则回退默认”的已声明含义落实；HTTP 上传体积上限、流式写入限制和前端预检同时对齐。若保留独立站点硬上限，应明确标为硬上限，不能继续把默认值暗中当硬上限。单位统一内部字节、界面明确 MB/MiB，不静默改变已有数值含义。
- 请求预算统一计算实际选入的全部媒体及其出现次数；同一文件多次进入内容块时，不能因选取阶段按 FileID 去重就漏算传输字节。预检可按元数据与编码公式预估，最终按实际序列化结果兜底，避免为了计数重复读取和编码大文件。
- 不再无说明丢掉旧图片：预算允许时继续提供；必须排除时，模型端保留可追溯的文件身份、已有可靠描述和原图本轮未提供的事实，用户端显示排除原因与重新选择入口。没有描述不能编造，也不默认额外调用模型生成描述。当前轮文件不能被静默省略后继续回答。
- 显示与错误文案使用同一最终选择结果，说明触及的是哪一层限制及实际有效值；将图数、大小、页数、token 预算、文件不可用等原因区分。取消错误的“未纳入也像已发送”和“只列本轮却写成完整总数”语义。
- 验收覆盖单文件/分类覆盖、0 不缩放、本轮加历史图片总数、图片加 PDF/音视频混合 payload、重复引用、达到边界/超过边界、分支/压缩/重试/切渠道，以及普通/临时/生图入口的适用差异。仅配置且未生效的参数不算完成。

### 2. 原生文件缓存核对

- 本轮目标是缓存链路正确，不承诺或强求供应商命中率；不将新增显式缓存/Files API 或提高命中率扩成默认实施范围。缓存不可用时，实际原件发送与文件可见性必须仍正确。
- 当前 `nativeInputCache` 只避免同一次发送及路由重试中反复读取本站存储，不是跨轮或上游缓存。Gemini PDF、音频、视频与图片仍通过 `inlineData` 编码发送；没有自动管理 Files API 文件资源或显式缓存对象。
- “可缓存稳定块”来自 prompt 规划的 `Cacheable` 标记，不是上游命中证据。Gemini `cachedContentTokenCount` 已读入缓存用量；显式 `cachedContent` 目前仅支持选项传入。需核对两种 Gemini 协议及实际模型的支持范围，不能因为内部标了 `CacheControl` 就声称创建了 Google 缓存。
- OpenAI 的 `previous_response_id`、prompt cache 和本站文件读取缓存分别检查。目前有默认分支、官方地址、prompt 指纹等续接限制；分支/压缩后重新发送原件是正确性兜底，不能依赖缓存来保存文件可见性。
- 对照 [Gemini 缓存](https://ai.google.dev/gemini-api/docs/caching)、[Gemini tokens](https://ai.google.dev/gemini-api/docs/tokens)、[OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching) 和 [会话状态](https://developers.openai.com/api/docs/guides/conversation-state)，核对稳定前缀、模型/路由边界、命中统计、缓存写入/读取费率与上下文容量。当前官方文档对 Argon/Interactions 与旧版 GenerateContent 的显式缓存支持不同，实施时按实际路由选择。
