# Chat01 分类回放实验

供方案审核的离线原型，不接入生产请求、不执行工具、不下载产物、不调用付费 API。输入为此前保存的 Chat01 content/SSE 抓包，输出为带原始字符位置的分类块；界面可回放实际 SSE 内容分片。非流式样本保持一次返回。

使用 Node 运行 `verify.mjs`，可传抓包目录；默认 `.cache/chat01-probes/20261104`。使用 Python 运行 `build.py <输出HTML绝对路径>` 生成对话内演示。抓包不提交仓库，脚本不会尝试重新获取缺失样本。

本次已验证十份真实样本：生图、多段 Answer 混合调用、搜索与命令、地图、非流式文件、多步代码修复、Office/PDF 原件核验、组件专项、协议字面量教程、音频及损坏数据修复。新增样本可选读取同级 `20261105/stress-a` 和 `stress-b`，缺少时不会请求上游。检查原始字符保全、真实 SSE 与 1/7/64/511 字符分片一致、四段正文保留和答案代码保护。另有十二项合成边界，包括嵌套围栏、行内/转义标记、heredoc、截断命令、损坏标题及畸形 URL。采集文件的 Windows 换行先规范为原 SSE 的 LF。

演示使用同一个增量解析核心；回退进度时重建该前缀状态。潜在协议标记和短代码边界暂存，普通正文随接收输出。未闭合组件逐步保存在独立块，超过阈值标记 oversized，完整性单独判断。文件卡片只表示识别到的链接，残留 sandbox 路径标为无下载地址；图片只显示位置与描述。演示不重新下载媒体。原始对照仅将 CDN 目录简写，底层分类与保全检查使用原始字符串。

这些样本不代表所有上游异常已经解决。无结构依据的自然语言不能保证区分正文与思考；原型尚不包括 SSE 快照去重、完整引用解码、所有工具语法、DIL 执行或生产持久化。未闭合组件没有可靠结束边界时保持原始块，不能把内部文字擅自解析成正文；正式实现还需统一诊断大小与异常恢复策略。`resourcesFor` 的固定域名识别仅用于已知探测样本，不能直接作为生产产物信任或下载策略。正式实现仍按待审核方案划分协议、解析、资源和界面边界。

9,000 秒心跳检查使用可控循环给解析器输入空文本，不实际等待、不调用 Pro；不代表 HTTP、任务恢复或两小时代理链路已经验收。新增五次付费请求及下载产物的本地核对见 [复杂任务实测](../../../docs/chat01-response-stress-20261105.md)。

2026-11-05 后续确认：兼容类型增加 Chat01，首版选择专用 Chat Completions 适配器；新建专用模型默认 Chat01 厂商及文本/图片/附件，已有共用平台模型不因一条路由而强制改厂商。非图片原件沿用原生标签，优先 HTTPS。复用预算、切模型报错和账务；现有 nativeBytes 不含图片，需要在共享预算框架补混合附件总量，不能把两个独立100 MiB预算误当合计100 MiB。官网组件复用基础展示与草稿交互，动态运行时和缺失API载荷仍是独立边界。
